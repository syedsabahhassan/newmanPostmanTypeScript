# Newman Postman API Automation — TypeScript Runner

> A CLI-based runner for scaling Postman collection execution using Newman and TypeScript. Born out of the frustration of running large test suites manually through the Postman GUI.

📖 Read the full story behind this on [Medium](https://medium.com/@sabahcomp/adopting-newman-to-scale-and-run-postman-collections-6a679df6f614)

---

## Why I Built This

Postman GUI is genuinely great for creating API tests — chaining requests, writing assertions, testing workflows. But once you're dealing with *x* collections, *y* requests, and *z* test data files, clicking through the Collection Runner just doesn't cut it anymore.

Newman is Postman's command-line collection runner, and it integrates cleanly with CI/CD servers and build systems. This repo is a TypeScript wrapper around Newman that lets you point it at a folder of collections and run them all — no GUI, no manual steps.

---

## The APIs Used for Testing

Rather than hunting for free public APIs (with all the signups and token headaches that come with them), I built my own simple RESTful APIs on AWS Lambda + API Gateway. Two straightforward GET endpoints:

- **Places to Visit** — `https://wdw1uuwkz7.execute-api.ap-southeast-2.amazonaws.com/default/placesAlreadyVisited`
- **Places Already Visited** — `https://lomfq0bog7.execute-api.ap-southeast-2.amazonaws.com/default/placesToVisit`

These are intentionally simple — the point is to show how Newman handles the collections, not to test a complex API.

## How the Runner Works

The main file `run-tests-postman.ts` does a few things:

1. Reads the environment config from `./environments/test.postman_environment.json`
2. Scans `./apitests/` for every file ending in `.postman_collection.json`
3. Loops through each collection and hands it to Newman
4. Generates an HTML report per collection under `./reports/`

```typescript
const configFile = "./environments/test.postman_environment.json";
const configData = fs.readFileSync(configFile, "utf8");
const configDataJson = JSON.parse(configData);
const testCollections = "./apitests";

const fileExtension = ".postman_collection.json";

listOfCollections = listDirSync(testCollections).filter(
  (fxt) => fxt.endsWith(fileExtension)
);

listOfCollections.forEach((element) => {
  console.info(`Running ${element} collection first`);

  try {
    newman.run({
      collection: require(`../\${testCollections}/\${element}`),
      environment: configDataJson,
      insecure: true,
      reporters: ["cli", "htmlextra"],
      reporter: {
        htmlextra: {
          export: `./reports/\${element}-executionResults.html`
        }
      }
    });
  } catch (err) {
    console.info(`new Execution of \${element} collection started`);
  }
});
```

Simple loop, no fuss. Every collection gets its own report file so you can see results per suite.

## Getting Started

### Prerequisites

- Node.js v14+
- npm

### Install

```bash
git clone https://github.com/syedsabahhassan/newmanPostmanTypeScript.git
cd newmanPostmanTypeScript
npm install
```

### Run the tests

```bash
npm run postman-test
```

Or directly:

```bash
npx ts-node run-tests-postman.ts
```

---

## Reports

After each run, HTML reports land in `./reports/` — one file per collection. They're generated by [newman-reporter-htmlextra](https://github.com/DannyDainton/newman-reporter-htmlextra) and include request/response details, test results, and a pass/fail summary. Open any `.html` file in your browser to review results.

---

## Postman Collections

The two collections in `apitests/` test the AWS Lambda-backed endpoints above. Each has:
- A `Successful response` assertion (status 200)
- A data-specific assertion (e.g. "Is India in the list")
- An environment variable for the base URL

You can swap these collections out for any of your own — just drop `.postman_collection.json` files into `apitests/` and the runner picks them up automatically.

## Extending This

A few natural next steps if you want to build on this:

- **Add more environments** — drop new `.postman_environment.json` files in `environments/` and update the config path
- **Parallelize collection runs** — the current loop is sequential; `Promise.all` can run them concurrently
- **Hook into CI/CD** — Newman's exit code reflects test failures, so this works cleanly in any pipeline
- **Add data-driven testing** — Newman supports iteration data files (`--iteration-data`) for running the same collection over multiple data sets
